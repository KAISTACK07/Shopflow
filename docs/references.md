# References and originality log

Rule for this project: we read public docs/repos for **ideas**, never copy code, comments, README text,
or file layouts. Every idea we borrow gets a row here, with what we did differently.
All links below were checked to resolve on 2026-09-26.

| # | Source | Idea taken | What we did differently / our own |
|---|---|---|---|
| 1 | PostgreSQL 16 docs — [Explicit Locking](https://www.postgresql.org/docs/16/explicit-locking.html), [SELECT … FOR UPDATE](https://www.postgresql.org/docs/16/sql-select.html) | Row-level locks, deadlock detection, "acquire locks in a consistent order" advice | Applied to checkout by sorting inventory rows by `product_id`; we'll write our own deadlock/oversell tests |
| 2 | PostgreSQL 16 docs — [Index Uniqueness Checks](https://www.postgresql.org/docs/16/index-unique-checks.html), [INSERT … ON CONFLICT](https://www.postgresql.org/docs/16/sql-insert.html) | An insert that collides with an *uncommitted* unique row waits for that transaction | Used as the concurrency guard for idempotency keys instead of an app-level lock |
| 3 | Brandur Leach — [Implementing Stripe-like Idempotency Keys in Postgres](https://brandur.org/idempotency-keys); Stripe — [Designing robust APIs with idempotency](https://stripe.com/blog/idempotency) | Keys scoped per user, store request fingerprint + response, reject reuse with different params | Much simpler: no multi-step "recovery points" — checkout is one DB transaction, so the key row and the order commit or roll back together |
| 4 | IETF draft — [The Idempotency-Key HTTP Header Field](https://datatracker.ietf.org/doc/draft-ietf-httpapi-idempotency-key-header/) | Header name, "same key + different payload is an error" | We return 409 for that case and 400 when the header is missing |
| 5 | Redis docs — [INCR, "Pattern: Rate limiter"](https://redis.io/docs/latest/commands/incr/) | Fixed-window counter with INCR + EXPIRE | Our own fail-open policy, `Retry-After` computation, and per-user key scheme |
| 6 | RFC 6585 §4 ([429](https://www.rfc-editor.org/rfc/rfc6585#section-4)), RFC 9110 ([Retry-After](https://www.rfc-editor.org/rfc/rfc9110#field.retry-after)) | Status code + header semantics | — |
| 7 | FastAPI docs — [OAuth2 with JWT](https://fastapi.tiangolo.com/tutorial/security/oauth2-jwt/) | Dependency-based "current user" pattern | JSON login body (not the OAuth2 form), argon2 instead of the tutorial's hasher, role loaded from DB |
| 8 | [fastapi/full-stack-fastapi-template](https://github.com/fastapi/full-stack-fastapi-template) | General idea of separating routers / models / config and running migrations on container start | Different layout (explicit service layer), sync SQLAlchemy instead of SQLModel, no generated client |
| 9 | OWASP — [Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html) | argon2id as the preferred algorithm | — |
| 10 | Alembic — [Tutorial](https://alembic.sqlalchemy.org/en/latest/tutorial.html) | Migration workflow | Migrations written/reviewed by hand, not blindly autogenerated |
| 11 | Python docs — [`contextvars`](https://docs.python.org/3/library/contextvars.html), [logging `extra`](https://docs.python.org/3/library/logging.html#logging.Logger.debug) | Per-request context without globals; attaching fields to a log record | Our formatter logs any non-standard record attribute as a JSON field, so no JSON-logging library is needed |
| 12 | SQLAlchemy docs — [Configuring Constraint Naming Conventions](https://docs.sqlalchemy.org/en/20/core/constraints.html) | `MetaData(naming_convention=...)` and `op.f()` to mark a name as final | Our constraint tests assert on those names; hit and fixed the double-prefix pitfall (`ck_users_ck_users_role`) ourselves |

## Original to this project

- Schema design (separate `inventory` table, movements ledger, `carts.user_id UNIQUE`).
- Checkout transaction ordering (idempotency insert → sorted locks → all-failures 409).
- Error envelope, JSON logging formatter, request-id middleware.
- All tests, including the 50-buyers/10-units and same-key concurrency tests.
